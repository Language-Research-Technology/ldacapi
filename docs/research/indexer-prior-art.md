## 1. Which crate metadata they index

### Oni structural indexer: one row per crate

- One `record` row per OCFL object, keyed by `crateId` (unique), holding `license`, `name`, `description`, `objectRoot` ([O: `src/indexer/structural.js:24-44`](https://github.com/Language-Research-Technology/oni/blob/82762f80190339999475a69f8699b6532afbbabb/src/indexer/structural.js#L24-L44), [O: `src/models/record.js`](https://github.com/Language-Research-Technology/oni/blob/82762f80190339999475a69f8699b6532afbbabb/src/models/record.js)).
- Side tables per crate: `rootType` (`@type`s), `rootMemberOf` (`memberOf` `@id`s, **with a NULL row when the root has no `memberOf`**, so "top level" is `memberOf IS NULL`), `rootConformsTo` ([O: `src/controllers/record.js:185-234`](https://github.com/Language-Research-Technology/oni/blob/82762f80190339999475a69f8699b6532afbbabb/src/controllers/record.js#L185-L234)).
- Only the **root dataset** is indexed; contained entities aren't rows. The `memberOf` property name is configurable (`api.memberOfField`, default `pcdm:memberOf`).
- Files: every file in the OCFL object's inventory becomes a `file` row (path, logical path, size, CRC32 computed by streaming the bytes) ([O: `structural.js:45-75`](https://github.com/Language-Research-Technology/oni/blob/82762f80190339999475a69f8699b6532afbbabb/src/indexer/structural.js#L45-L75)). Files come from OCFL, not from the crate's `hasPart`.
- A crate is skipped (warning) when it has no root dataset, its root `@id` is `./`, or it has no licence and no configured default ([O: `src/indexer/indexer.js:31-46`](https://github.com/Language-Research-Technology/oni/blob/82762f80190339999475a69f8699b6532afbbabb/src/indexer/indexer.js#L31-L46)). `api.skipByMatch` regexes skip objects by id ([O: `src/services/indexer.js:128-135`](https://github.com/Language-Research-Technology/oni/blob/82762f80190339999475a69f8699b6532afbbabb/src/services/indexer.js#L128-L135)).
- The `/object?memberOf=…&conformsTo=…` API is a query over these tables; with `deep`, Oni assembles a collection by following `rootMemberOf` children and merging their graphs ([O: `record.js:311-335`](https://github.com/Language-Research-Technology/oni/blob/82762f80190339999475a69f8699b6532afbbabb/src/controllers/record.js#L311-L335)).

### Oni search indexer (in-process, current)

- Walks the crate from the root down `pcdm:hasMember`, `@reverse pcdm:hasMember`, `hasPart` and `@reverse partOf`, tracking the chain of parents ([O: `src/indexer/search.js:111-146`](https://github.com/Language-Research-Technology/oni/blob/82762f80190339999475a69f8699b6532afbbabb/src/indexer/search.js#L111-L146)).
- **Profile filter:** an entity gets a document only if its `conformsTo` is one of the configured profile URIs (`api.conformsTo.collection` / `.object` = `https://w3id.org/ldac/profile#Collection` / `#Object`) **or** its `@type` includes `File` ([O: `search.js:148-153`](https://github.com/Language-Research-Technology/oni/blob/82762f80190339999475a69f8699b6532afbbabb/src/indexer/search.js#L148-L153), [O: `configuration/default.js:638-642`](https://github.com/Language-Research-Technology/oni/blob/82762f80190339999475a69f8699b6532afbbabb/configuration/default.js#L638-L642)). People, places, languages etc. are only embedded in other documents.
- Each document is `crate.getTree({root: entity, depth: 1})`, i.e. the entity with its linked entities inlined one level, plus derived fields: `_crateId`, `_memberOf` (basic `@id`/`@type`/`name`), `_isTopLevel` when there is no `memberOf`, `_root` (this crate's root dataset), `_parent`, `_collectionStack` (the in-crate parents' `@id`s), `_metadataIsPublic`, `_metadataLicense`, `_geolocation`/`_centroid` from `contentLocation`/`spatialCoverage` WKT ([O: `search.js:154-176`](https://github.com/Language-Research-Technology/oni/blob/82762f80190339999475a69f8699b6532afbbabb/src/indexer/search.js#L154-L176)).
- Text: files reached via `indexableText` with a `text/*` `encodingFormat` get `_text` read from OCFL ([O: `search.js:234-250`](https://github.com/Language-Research-Technology/oni/blob/82762f80190339999475a69f8699b6532afbbabb/src/indexer/search.js#L234-L250)).
- `_root` and `_collectionStack` stop at the crate boundary: this indexer doesn't look at other crates.

### oni-ui CLI indexer (what LDaCA ran)

- **Traverses across crates top-down.** It starts with `GET /api/object?memberOf=&conformsTo=<Collection profile>` (Oni's structural index: top-level collections), indexes each, and for a collection without a local `pcdm:hasMember` it asks Oni for the children (`memberOf=<id>`) as collections then as objects, recursing ([U: `lib/Indexer.js:178-239`, `:345-349`](https://github.com/Language-Research-Technology/oni-ui/blob/20a10bc8c3bc6db878ba8c85bcb455842001df59/lib/Indexer.js#L178-L239), [U: `elastic-ocfl-oni-index.js:84-85`](https://github.com/Language-Research-Technology/oni-ui/blob/20a10bc8c3bc6db878ba8c85bcb455842001df59/elastic-ocfl-oni-index.js#L84-L85)). So it needs the structural index first, and it never reaches a crate whose ancestor chain doesn't lead to a top-level collection.
- **Bundled crates:** if a collection has `pcdm:hasMember`, those members are indexed from the same crate, as collections if they conform to the Collection profile **and** have `@type` `RepositoryCollection`, as objects for the Object profile **and** `RepositoryObject` ([U: `Indexer.js:308-344`](https://github.com/Language-Research-Technology/oni-ui/blob/20a10bc8c3bc6db878ba8c85bcb455842001df59/lib/Indexer.js#L308-L344)). Root crates are matched on `conformsTo` alone.
- **Files:** each object's `hasPart` entries become file documents ([U: `Indexer.js:415-426`, `:444-549`](https://github.com/Language-Research-Technology/oni-ui/blob/20a10bc8c3bc6db878ba8c85bcb455842001df59/lib/Indexer.js#L415-L549)).
- **Derived fields carried down the traversal:** `_root` = the **top-level** collection (crossing crates), `_memberOf` = the immediate parent only (adding the ancestors "was commented out because in some cases the memberOf can be overwhelming with too many children", [U: `Indexer.js:301-306`](https://github.com/Language-Research-Technology/oni-ui/blob/20a10bc8c3bc6db878ba8c85bcb455842001df59/lib/Indexer.js#L301-L306)), `_collectionStack` = every ancestor collection `@id`/name across crates, `_mainCollection` / `_subCollection` = that stack split into the top-level one and the rest, `_isTopLevel`, `_isOCFL` (whether the entity is a crate root), `_parent` on files ([U: `Indexer.js:254-300`, `:366-398`, `:466-478`](https://github.com/Language-Research-Technology/oni-ui/blob/20a10bc8c3bc6db878ba8c85bcb455842001df59/lib/Indexer.js#L254-L478)). A collection document drops its own `memberOf` and `hasPart` before `getTree` so the document doesn't inline them.
- **`ldac:` properties:** before indexing, `normalizeLdac` fetches `https://w3id.org/ldac/context` and renames every unprefixed property whose context IRI is in `https://w3id.org/ldac/terms#` to `ldac:<name>` (e.g. `communicationMode` → `ldac:communicationMode`), so crates written with either spelling index the same way ([U: `lib/normalize.js`](https://github.com/Language-Research-Technology/oni-ui/blob/20a10bc8c3bc6db878ba8c85bcb455842001df59/lib/normalize.js), [U: `Indexer.js:207-210`](https://github.com/Language-Research-Technology/oni-ui/blob/20a10bc8c3bc6db878ba8c85bcb455842001df59/lib/Indexer.js#L207-L210)).
- **Text:** a file gets `_text` only when an entity links it through `@reverse` `indexableText` / `ldac:indexableText` / `mainText` / `ldac:mainText` (re-checked against the forward property), it has a `text/*` `encodingFormat`, and its licence doesn't set `allowTextIndex: false`. A missing file sets `_error: 'file_not_found'` ([U: `Indexer.js:485-531`](https://github.com/Language-Research-Technology/oni-ui/blob/20a10bc8c3bc6db878ba8c85bcb455842001df59/lib/Indexer.js#L485-L531)).
- Failed documents are written as JSON files to the log folder for inspection ([U: `Indexer.js:50-55`](https://github.com/Language-Research-Technology/oni-ui/blob/20a10bc8c3bc6db878ba8c85bcb455842001df59/lib/Indexer.js#L50-L55)).

### arocapi-ldaca and arocapi's `exploder` branch

- `explodeCrate` turns **every** entity whose `@type` includes `RepositoryCollection`, `RepositoryObject` or `File` into its own small crate: `getTree({depth: 2})` of the entity as root, plus `Dataset` and a forced `conformsTo` ("TODO: Check conformsTo") ([A: `lib/explodeCrate.js`](https://github.com/Language-Research-Technology/arocapi-ldaca/blob/fa77267dbcf399757eb3571010af61f2e9f878eb/lib/explodeCrate.js); identical on arocapi's [`exploder` branch](https://github.com/crate-works/arocapi/blob/148fffef1eca92dd260bcb00d8745f9ac836cc36/lib/explodeCrate.js)). This is the same idea as ldacapi's ADR 0004 (entity metadata is a virtual crate), but stored per entity at index time.
- Each small crate became an `Entity` row (`storageObjectId`, `rocrateId`, `memberOf`, `recordType`, the small crate as `rocrate` JSON); `root` was left `null` ([A: `lib/addCrate.js:31-57`](https://github.com/Language-Research-Technology/arocapi-ldaca/blob/fa77267dbcf399757eb3571010af61f2e9f878eb/lib/addCrate.js#L31-L57), [A: `prisma/schema.prisma`](https://github.com/Language-Research-Technology/arocapi-ldaca/blob/fa77267dbcf399757eb3571010af61f2e9f878eb/prisma/schema.prisma)). The search documents' `inLanguage`, `mediaType` and `communicationMode` were **random dummy values** ([A: `addCrate.js:65-83`](https://github.com/Language-Research-Technology/arocapi-ldaca/blob/fa77267dbcf399757eb3571010af61f2e9f878eb/lib/addCrate.js#L65-L83)).

### arocapi beta.10's own loaders

- `example/data/seed.ts` reads distributed example crates (one collection crate, one crate per item) and writes one `Entity` per collection, item and file, setting `memberOf` to the parent and `rootCollection` to the collection, files carrying `meta.remapRootTo` for their virtual crate ([R: `example/data/seed.ts:60-205`](https://github.com/crate-works/arocapi/blob/f4cd98e3ac6ec668f5586f002d8247c8fb32427c/example/data/seed.ts#L60-L205)). It knows the hierarchy from the directory layout, not from crate metadata.
- `scripts/loadEntities.ts` copies entities from PARADISEC's Oni API and fills `inLanguage`/`mediaType`/`communicationMode` with dummy values ([R: `scripts/loadEntities.ts`](https://github.com/crate-works/arocapi/blob/f4cd98e3ac6ec668f5586f002d8247c8fb32427c/scripts/loadEntities.ts)).
- Neither is a general crate indexer; arocapi ships none.

### LDaC profile rules an indexer relies on

- Two layouts: **distributed** (one crate per Collection/Object, linked by `pcdm:memberOf` to a "resolvable ID … of the parent Collection"; `pcdm:hasMember` optional and "should not include descriptions of Objects that are stored elsewhere") and **bundled** (one crate holds the whole collection) ([P: `masp-profile/profile-text.md:95-110`, `:163-210`](https://github.com/Language-Research-Technology/ldac-profile/blob/702c23aef949068705bd8e7799b4302246fc9127/masp-profile/profile-text.md#L95-L110)).
- Distributed is recommended when "more than one data reuse license" applies or the collection isn't stable ([P: `profile-text.md:176-189`](https://github.com/Language-Research-Technology/ldac-profile/blob/702c23aef949068705bd8e7799b4302246fc9127/masp-profile/profile-text.md#L176-L189)).
- No prior art uses a `rootCollection` property from the crate; all derive it (oni-ui by traversal, arocapi's seed from the directory, Nabu from its own tables).

## 2. Entities shared between crates (same `@id` in several crates)

None of them solves this; each sidesteps it:

- **Oni structural:** only crate roots are rows, keyed by unique `crateId`, so shared contained entities never collide. A duplicate `crateId` makes `Record.create` throw, which `createRecord` catches and logs ([O: `record.js:185-234`](https://github.com/Language-Research-Technology/oni/blob/82762f80190339999475a69f8699b6532afbbabb/src/controllers/record.js#L185-L234)).
- **Oni search:** the document id is the entity `@id` if it starts with the crate id, otherwise `<crateId>/<entityId>`, written with `update … doc_as_upsert` ([O: `search.js:183-192`](https://github.com/Language-Research-Technology/oni/blob/82762f80190339999475a69f8699b6532afbbabb/src/indexer/search.js#L183-L192)). So an entity whose `@id` is outside the crate's namespace gets **one document per crate**; one inside it is upserted (last write wins).
- **oni-ui indexer:** document id `<top-level collection>/<crateId>/<entity @id>` ([U: `Indexer.js:290`, `:406`, `:537`](https://github.com/Language-Research-Technology/oni-ui/blob/20a10bc8c3bc6db878ba8c85bcb455842001df59/lib/Indexer.js#L290)), so a shared entity is **duplicated per crate (and per top-level collection)**. Only Collection/Object/File entities get documents, so shared people, places and languages are embedded copies, never their own documents.
- **arocapi-ldaca:** the `Entity` primary key was an autoincrement `id`; the composite `@@id([storageObjectId, rocrateId])` was commented out ([A: `schema.prisma:14-29`](https://github.com/Language-Research-Technology/arocapi-ldaca/blob/fa77267dbcf399757eb3571010af61f2e9f878eb/prisma/schema.prisma#L14-L29)), so a shared entity was a row per crate occurrence.
- **Nabu:** the source of truth is relational (collections → items → essences); there are no crates to share entities between.
- **Deleting:** Oni deletes structural rows by `crateId` **prefix** (`Op.startsWith`), relying on child crate ids starting with the parent's id; the search index is only deleted whole ([O: `structural.js:82-87`, `search.js:64-70`](https://github.com/Language-Research-Technology/oni/blob/82762f80190339999475a69f8699b6532afbbabb/src/indexer/structural.js#L82-L87)). Reindexing one crate also uses that prefix "as a hack" to include subcollections ([O: `services/indexer.js:142-153`](https://github.com/Language-Research-Technology/oni/blob/82762f80190339999475a69f8699b6532afbbabb/src/services/indexer.js#L142-L153)).

Borrowable, as options for #35: per-crate copies keyed by `(crate, @id)` (Oni search, oni-ui, arocapi-ldaca) are the only working precedent; none had a single shared row with a crate link table or reference count.

## 3. Aggregates for Oni (counts, `language`, `communicationMode`, `mediaType`)

Two precedents, opposite approaches:

### Query-time aggregation over ancestors stored on each document (oni-ui)

- Each document carries `_collectionStack` (all ancestor collections across crates), `_memberOf` (immediate parent), `_parent` (for files) and `_root` (top-level collection).
- The portal computes a collection's summary with OpenSearch queries at view time: subcollections = `_memberOf.@id = id` + Collection profile; objects = `_collectionStack.@id = id` + Object profile; facets (language, communication mode, `@type`, which gives the File count) = aggregations over `_collectionStack.@id = id`. For an object, the summary is over `_parent.@id = id` ([U: `portal/src/components/SearchDetailElement.component.vue:200-228`](https://github.com/Language-Research-Technology/oni-ui/blob/20a10bc8c3bc6db878ba8c85bcb455842001df59/portal/src/components/SearchDetailElement.component.vue#L200-L228), [U: `AccessInfo.component.vue:178-185`](https://github.com/Language-Research-Technology/oni-ui/blob/20a10bc8c3bc6db878ba8c85bcb455842001df59/portal/src/components/AccessInfo.component.vue#L178-L185)).
- The facet fields are configured in Oni (`inLanguage.name.@value`, `communicationMode.name.@value`, `license.@id`, `_memberOf.name.@value`, …; [O: `configuration/default.js:497-565`](https://github.com/Language-Research-Technology/oni/blob/82762f80190339999475a69f8699b6532afbbabb/configuration/default.js#L497-L565)).
- **Refreshing ancestors:** nothing is stored on ancestors, so ancestors never go stale. What can go stale is the copy of ancestor ids/names on **descendants** (a moved or renamed collection). There's no incremental path: the CLI deletes the index and walks from the top again ([U: `elastic-ocfl-oni-index.js:17-29`](https://github.com/Language-Research-Technology/oni-ui/blob/20a10bc8c3bc6db878ba8c85bcb455842001df59/elastic-ocfl-oni-index.js#L17-L29)).

### Precomputed counts and lists in a table, refreshed on write (Nabu)

- An `entities` table holds, per collection / item / essence, `items_count`, `essences_count`, `media_types` (comma-joined distinct MIME types), `private`, `member_of` ([N: `app/models/entity.rb`](https://github.com/nabu-catalog/nabu/blob/f37b61a31eca6c84fe5b322d4e421fba5946c9fe/app/models/entity.rb)). It started as a SQL view doing the `COUNT(DISTINCT …)`/`GROUP_CONCAT` ([N: `db/views/entities_v06.sql`](https://github.com/nabu-catalog/nabu/blob/f37b61a31eca6c84fe5b322d4e421fba5946c9fe/db/views/entities_v06.sql)) and was converted to a real table in December 2025 ([N: `db/migrate/20251215100648_convert_entities_view_to_table.rb`](https://github.com/nabu-catalog/nabu/blob/f37b61a31eca6c84fe5b322d4e421fba5946c9fe/db/migrate/20251215100648_convert_entities_view_to_table.rb)).
- **Refreshing ancestors:** `after_commit` callbacks recompute the parent rows. An essence change updates its item's and its collection's `media_types` and `essences_count`, then queues async search reindexes of both ([N: `app/models/essence.rb:408-422`](https://github.com/nabu-catalog/nabu/blob/f37b61a31eca6c84fe5b322d4e421fba5946c9fe/app/models/essence.rb#L408-L422)); an item change updates its collection's `items_count` ([N: `app/models/item.rb:770-774`](https://github.com/nabu-catalog/nabu/blob/f37b61a31eca6c84fe5b322d4e421fba5946c9fe/app/models/item.rb#L770-L774)). The hierarchy is fixed at two levels, so the ancestors are always known.
- The Oni entity response reads those columns: `counts.objects`, `counts.files`, `mediaType`; `language` comes from item content languages or collection languages; `communicationMode` is a TODO ([N: `app/views/api/v1/oni/_entity.json.jb:9-12`, `:92-115`](https://github.com/nabu-catalog/nabu/blob/f37b61a31eca6c84fe5b322d4e421fba5946c9fe/app/views/api/v1/oni/_entity.json.jb#L9-L115)).
- The search documents also carry the children's values (`encodingFormat: essences.map(&:mimetype)` on a collection; [N: `app/models/collection.rb:267-285`](https://github.com/nabu-catalog/nabu/blob/f37b61a31eca6c84fe5b322d4e421fba5946c9fe/app/models/collection.rb#L267-L285)), i.e. aggregates pushed up onto the ancestor's document.

### arocapi

- The dev server's Oni transformer returns `counts: {collections: 0, objects: 0, files: 0}` hard-coded ([R: `src/index.dev.ts:74-85`](https://github.com/crate-works/arocapi/blob/f4cd98e3ac6ec668f5586f002d8247c8fb32427c/src/index.dev.ts#L74-L85)); arocapi has no aggregate support of its own.

## 4. Licence and access control from crate metadata

### What the LDaC profile defines

On a `ldac:DataReuseLicense` ([P: `masp-profile/profile-crate/ro-crate-metadata.json`](https://github.com/Language-Research-Technology/ldac-profile/blob/702c23aef949068705bd8e7799b4302246fc9127/masp-profile/profile-crate/ro-crate-metadata.json)):

- `ldac:access`: `ldac:OpenAccess` ("does not require any specific authorization step") or `ldac:AuthorizedAccess`.
- `ldac:authorizationWorkflow`: `ldac:AuthorizationByApplication`, `ldac:AuthorizationByInvitation`, `ldac:AgreeToTerms`, `ldac:AccessControlList` (with `ldac:accessControlList` pointing at a user list), `ldac:SelfAuthorization`.
- `ldac:openAccessIndex`: public index types a licence allows (e.g. full-text indexing for discovery even when the item isn't open).

No prior art reads `ldac:access`, `ldac:authorizationWorkflow` or `ldac:openAccessIndex`.

### Oni and the oni-ui indexer: resolve the licence at index time, authorise at query time

- **Content licence resolution:** entity's own `license` → parent's (Oni search) or object's / root's (oni-ui) → configured default (`api.license.default`, commented out in Oni's default config). The value must resolve to an **entity in the crate**; a bare URI that isn't in the graph is rejected ("Invalid license" / "Licenses should be @ids of items in rocrate") and falls through to the default ([O: `search.js:263-273`](https://github.com/Language-Research-Technology/oni/blob/82762f80190339999475a69f8699b6532afbbabb/src/indexer/search.js#L263-L273), [U: `Indexer.js:258-266`, `:369-378`, `:451-463`, `:558-578`](https://github.com/Language-Research-Technology/oni-ui/blob/20a10bc8c3bc6db878ba8c85bcb455842001df59/lib/Indexer.js#L558-L578)). With no licence and no default the entity (or whole crate, in the structural indexer) is skipped. Note: Oni's search indexer assigns the resolved licence to `entity.licence` (British spelling) rather than `license` ([O: `search.js:162`](https://github.com/Language-Research-Technology/oni/blob/82762f80190339999475a69f8699b6532afbbabb/src/indexer/search.js#L162)).
- **Metadata licence:** the `license` on the `ro-crate-metadata.json` descriptor, with its `metadataIsPublic`, stored as `_metadataLicense` / `_metadataIsPublic`; otherwise a configured default (CC BY 4.0, public). oni-ui skips the entity if there's neither ([O: `search.js:275-289`](https://github.com/Language-Research-Technology/oni/blob/82762f80190339999475a69f8699b6532afbbabb/src/indexer/search.js#L275-L289), [U: `Indexer.js:667-694`](https://github.com/Language-Research-Technology/oni-ui/blob/20a10bc8c3bc6db878ba8c85bcb455842001df59/lib/Indexer.js#L667-L694)).
- **Text indexing permission:** the licence entity's `allowTextIndex` (oni-ui: index unless `false`) ([U: `Indexer.js:487-491`](https://github.com/Language-Research-Technology/oni-ui/blob/20a10bc8c3bc6db878ba8c85bcb455842001df59/lib/Indexer.js#L487-L491)). This is the predecessor of `ldac:openAccessIndex`.
- **Authorisation:** configuration, not crate metadata, decides who may access. `api.licenses` maps licence URIs to groups (e.g. the four Sydney Speaks licences, `#restricted`), each with an enrolment URL; **a licence not in the list is open to everyone** ([O: `src/services/license.js:6-46`](https://github.com/Language-Research-Technology/oni/blob/82762f80190339999475a69f8699b6532afbbabb/src/services/license.js#L6-L46), [O: `configuration/default.js:406-449`](https://github.com/Language-Research-Technology/oni/blob/82762f80190339999475a69f8699b6532afbbabb/configuration/default.js#L406-L449)). Group membership comes from the identity provider (CILogon/COmanage, GitHub).
- **Enforcement:** search hits a user can't access are redacted, not removed: if `_metadataIsPublic` only `_text` is dropped; otherwise the source is cut to `@id`, `@type`, `_memberOf`, `_parent`, `_crateId`, `name`, `license` plus `error: 'not_authorized'` ([O: `src/services/elastic.js:16-60`](https://github.com/Language-Research-Technology/oni/blob/82762f80190339999475a69f8699b6532afbbabb/src/services/elastic.js#L16-L60)). Object and file routes check the crate's `record.license` ([O: `src/middleware/auth.js:96-120`](https://github.com/Language-Research-Technology/oni/blob/82762f80190339999475a69f8699b6532afbbabb/src/middleware/auth.js#L96-L120)).

### Nabu: map its own access conditions to LDaC workflow terms

- `accessControl` in the Oni response is derived from the item/collection's access condition: private → `AccessControlList`; none → `AuthorizationByInvitation`; "Open (subject to agreeing to PDSC access conditions)" → `AgreeToTerms`; "Closed …", "Mixed …" or "-" → `AccessControlList`; otherwise `Public` ([N: `_entity.json.jb:96-110`](https://github.com/nabu-catalog/nabu/blob/f37b61a31eca6c84fe5b322d4e421fba5946c9fe/app/views/api/v1/oni/_entity.json.jb#L96-L110)). It is computed per request from relational data, not stored.
- `access.content` / `access.metadata` booleans come from the requesting user's abilities (CanCan) ([N: `_entity.json.jb:13-16`, `:21`, `:45-50`, `:73-80`](https://github.com/nabu-catalog/nabu/blob/f37b61a31eca6c84fe5b322d4e421fba5946c9fe/app/views/api/v1/oni/_entity.json.jb#L13-L80)).

### arocapi

- Stores `metadataLicenseId` / `contentLicenseId` on `Entity` and leaves the rule to the application through `meta.accessControl` and its `access` / visibility filter hooks; its seed falls back to CC BY 4.0 for both ([R: `example/data/seed.ts:83-90`, `:128-131`](https://github.com/crate-works/arocapi/blob/f4cd98e3ac6ec668f5586f002d8247c8fb32427c/example/data/seed.ts#L83-L131), [R: `website/examples/configuration/access-function.ts`](https://github.com/crate-works/arocapi/blob/f4cd98e3ac6ec668f5586f002d8247c8fb32427c/website/examples/configuration/access-function.ts)).

## What ldacapi could borrow (options, not decisions)

- **Profile filter:** LDaCA's prior indexers decide what gets its own row/document by `conformsTo` against the LDaC Collection/Object profile URIs, plus `@type` `File`; oni-ui also checks `RepositoryCollection`/`RepositoryObject` for members inside a bundled crate. Others (people, places, languages) are only embedded.
- **`ldac:` normalisation:** oni-ui's rename of unprefixed LDaC terms to `ldac:` via the context lets one field name serve both spellings. It fetched the context over the network on every run; a bundled copy is the obvious variant.
- **Cross-crate ancestry:** oni-ui's top-down walk gives `_root` and `_collectionStack` across crates, but only as a full rebuild. ldacapi's bottom-up `rootCollection` lookup (#60) gives the same answer per crate; storing the full ancestor list (not just `rootCollection`) on each document is the oni-ui shape.
- **Aggregates:** two working shapes: (a) ancestors on each document, aggregated in OpenSearch at query time (oni-ui; nothing to refresh on ancestors, descendants go stale on move/rename); (b) precomputed columns refreshed up the chain on write (Nabu; simple because its depth is fixed at two). #47's "ancestors stored on each search document" option is (a).
- **Shared entities:** the only precedent is a copy per crate keyed by `(crate, @id)`. No prior art shows a shared row with a crate link table or reference counts.
- **Licence resolution:** entity → parent → root → configured default, requiring the licence to be an entity in the crate; metadata licence from the descriptor with `metadataIsPublic`; `allowTextIndex` gating `_text`. The `accessControl` value set used by Oni clients is the LDaC authorisation workflow vocabulary, as Nabu maps it.
- **Authorisation config:** Oni's "licence URI → group, unlisted licences are open" table is how restricted Sydney Speaks access worked before `ldac:authorizationWorkflow`.
- **Where it runs:** every LDaCA precedent is either in the API process with in-memory state (Oni) or a run-to-completion CLI (oni-ui, arocapi-ldaca, oni-express). The only one with persisted queue state is Nabu (database-backed job queue for search reindexing).
- **Pitfalls seen in prior art:** id-prefix matching to find a collection's descendants (Oni), deleting the whole search index to reindex anything (Oni, oni-ui), `refresh: true` per document (Oni, oni-ui), dummy aggregate data (arocapi-ldaca, arocapi's loader), `licence`/`license` spelling slip (Oni).
